# `proscenium_sync.synchronization`

The synchronization transaction ([Synchronization Transaction](../../../../../docs/spec/pipeline.md#synchronization-transaction)): one attempt to display a binding's source, from acquisition through retirement; the cache call, which caches time codes in the published generation ([Cached Time Codes](../../../../../docs/spec/pipeline.md#cached-time-codes)); and the application layer they apply display plans with. Tier 4: `proscenium_sync.bindings` calls it, and it may import every unit below it ([import rules](../README.md#import-rules)). M7 replaces M5's stub application layer: preparation is M7's, and keying cached time codes still the stub's until M7's Phase D.

| File | Holds |
|---|---|
| `__init__.py` | The package's exports: `synchronize`, `cache`, and `retry_cleanup`, from `transaction`, `time_code_caching`, and `cleanup_retry`. Evaluation, the application layer, prepared work, publication, retirement, and removal are theirs. |
| `application.py` | The application layer: `prepare` makes the partitions of a plan's drawn copies it's given, in that order, each a copy's object drawing its bounds and its bounds mesh, under an unselectable shear parent when the plan splits its world transform, an empty marker's object holding no data, named so each object and its bounds mesh land at the end of Blender's sorted lists (`~<generation>.<copy_position> <prim name>`), in prepared work's staging collection, which no scene links, keyed by the published entries whose identities they have, and tracks each as it's made. It reads the copy table's buffers, converts only those copies' resources and geometry descriptions, releases every buffer view before it returns (SNAP-13), and imports nothing that reads a stage (APP-08). A Blender operation on a resource that fails raises `ResourceOperationError`, naming the resource's role and source entity, a runtime failure. Preparation only creates datablocks, so it changes nothing the published generation reaches (TXN-05). Also the representation version it applies, which the planning context names, and the matrices, bounds, and managed names `time_code_keying` and `local_updates` share. |
| `time_code_keying.py` | `key_time_codes`: keys each published copy a cache call finds varying, or every copy, at its time codes, constant until the next key: its object's transform and hide flags and its shear parent's transform, in one action per copy, a slot for each, and a copy's bounds that vary as position samples of its bounds mesh, shown through the display's one frames group (`attribute_samples`), made and tracked when the copy is first keyed and keyed then at the generation's own time code and those cached before, as they showed. A placeholder that is a box at some time codes and a marker at others gets an object of the other form, place 1 among the copy's objects, made, tracked, and linked, hidden wherever the plan draws the first form, as the first is wherever it draws the other. A copy drawn only at a cached time code has its partition made by `application.prepare` and linked into the destination, hidden wherever the plan lacks it, as a copy the plan lacks at a time code is hidden there. A copy sheared only at a cached time code gets a shear parent, made, tracked, linked into the destination, and the identity where the copy isn't sheared. Each change to a published resource has its undo in the prepared work first; it returns the manifest changes. |
| `time_code_caching.py` | `cache`, a cache call for a binding the caller has found usable: it evaluates and plans the source at each time code the published generation hasn't cached, under the generation's payload policy, before changing any Blender data, compares each plan with the generation's held one through the plan diff to find the copies that vary, then has the application layer key them, adds its actions to the manifest by entry, and adds the time codes to the generation record. It publishes no generation and records no last attempt. A generation at the default time code has nothing to cache, so the call succeeds (CACHE-06); one with no generation, or whose source revision differs from the generation's, which it checks even with nothing new to cache, fails with a `needs-synchronization` diagnostic (CACHE-05). A call that fails caches none of its time codes: it reverts its keys and the manifest and disposes of its actions, each whose removal fails entering the ledger (CACHE-03). |
| `cleanup_retry.py` | `retry_cleanup`, the explicit retry of a binding's pending cleanup, without USD access: its leftovers are removed through `datablock_removal.remove_unused`, the ledger's Text aside, and one that still can't be removed stays retryable with a fresh diagnostic. Resolved entries leave the ledger with their diagnostics, and a ledger that can't be read refuses. |
| `evaluation.py` | What the transaction and a cache call share before changing Blender data: `evaluate_display_plans`, the plan at each of some time codes, reporting to the caller's collector the source state's diagnostics (`source_state_diagnostics`, the dirty-layer diagnostic a display reports), the verification mode's, and each plan's, captured from the binding's kept chain, built when it has none and released by a capture that fails or is discarded, checked against a capture through a new chain under the verification mode, within `BindingStages.monitor_evaluation_layer_changes()` so a layer changing meanwhile discards them (CONS-03), or none, reporting the fatal diagnostic saying why; and `plan_diagnostics`, a plan's source-side diagnostics as the binding's. The caller supplies the target scene's unit scale and the application's representation version; evaluation builds the planning context without importing the application layer. On import it checks that every code the planner reports is in `DiagnosticCode`. |
| `capture_verification.py` | The opt-in verification mode (`PROSCENIUM_VERIFY_CAPTURE`, `enabled`): `mismatch_diagnostics`, a `capture-mismatch` verification diagnostic for each drawn copy whose plan from the kept chain differs from a full re-read's, the first ten by source path and one counting the rest ([Change Discovery](../../../../../docs/spec/incremental.md#change-discovery)). |
| `preparation_resources.py` | `PreparationResources`, what a preparation has made, which the application layer's preparation and cache calls share: `cleanup_tracking_diagnostic` says why none can be made when the ledger couldn't record a failed disposal; `track` holds each resource before anything else can fail (TXN-08), `undo` how to undo each change a cache call makes to a published resource, which `revert_published_resource_changes` runs in reverse, and `dispose` removes it all through `datablock_removal.remove_unused`, the staging collection aside, recording in the pending-cleanup ledger only each removal that fails, retryable, with its cleanup diagnostic; `abort` reports a failure and does both, reporting each removal that failed; after publication, `remove_staging_and_clear_tracking` lets go of it. |
| `partition_replacement.py` | Which partitions a synchronization prepares, which kept copies it updates in place, and which published entries it replaces (`partitions_to_replace`): against the shown generation's held plan, the partitions the plan diff builds or whose resources differ, and the kept copies that only moved, changed their bounds, changed their participation, or hold a cached generation's keys (`changed_partitions`), or with none, every partition (`every_partition`). It decides from the planner's plan diff and the published manifest's partitions, which `kept_manifests` keeps beside the manifest (`copy_partitions`). A kept copy any of whose partition's resources unmanaged content uses is rebuilt instead (CHG-06, OWN-08), as is one that lost a published resource or whose published partition isn't the plan's. |
| `local_updates.py` | Kept copies changed in place: `prepare_updates` makes each replacement bounds mesh beside the display, held in the prepared work under the replaced mesh's key; `apply_updates`, at publication, sets each moved copy's matrices, repoints a copy's object at its replacement mesh, and sets hide flags together through an unlinked collection, each undone on failure, a transform from its stored components (`Transform`). A replacement mesh takes the synchronization's next managed name. |
| `publication.py` | `publish`, the switch to prepared work: the destination's links to the prepared objects and from those they replace, the manifest by entry, and the generation record, each written only when it changes and undone in reverse when a later one fails, so the published generation is all old or all new (TXN-06); it returns the obsolete resources for retirement. |
| `transaction.py` | `synchronize`, the transaction's steps for a binding the caller has found usable: it refuses one whose records it needs can't be read, warns of each other scene linking the destination whose unit scale differs from the target scene's (`unit-scale-mismatch`, before Blender data changes), then acquires, evaluates and plans through `evaluation` (discarding the attempt if a contributing layer changes meanwhile), prepares the partitions `partition_replacement` names against the shown generation's held plan, or every one without it, checks that the destination wasn't removed meanwhile (`destination-invalid`, a state change), and publishes, each failure before publication a fatal diagnostic, preparation's naming the resource it was making, with prepared work disposed of and each disposal that failed reported, and retires, a ledger write that fails raising as a defect, and records the last attempt on every outcome, writing it only when it differs from the one recorded (STATE-03). It holds each published generation's plan, and returns a `SynchronizationOutcome`: the result, and whether the attempt committed, writing anything of the published generation. It pushes no undo step; `Bindings` does, for one that committed (UNDO-10). |
| `attribute_samples.py` | A mesh's values at cached time codes, ported from the bridge's: each varying attribute's sample at a time code is an attribute `<name>@<sample>` on the mesh, which a frames modifier first in its object's stack shows for its keyed Sample input, through the frames group, a Geometry Nodes group per set of varying attributes; sample `BASE` shows the mesh's own values. M7 samples a bounds mesh's positions. |
| `datablock_removal.py` | `remove_unused`, the removal disposal, retirement, and a cleanup retry share: from each datablock's users, read once (after updating the view layers of a Scene they name, so a base left from before an undo push isn't taken for a use), it removes those nothing else uses a level at a time, users first, releases intact those something else uses, and leaves pending, with why, those whose removal or whose user's failed (`RemovalOutcome`). Each level goes through `remove_datablocks_collecting_failures`, one `bpy.data.batch_remove` call, since each call scans the file, and only when it raises is it halved until each that fails is alone, never passing one already removed, on which Blender crashes. |
| `retirement.py` | `retire`, which removes the obsolete resources publication returned through `datablock_removal.remove_unused`. Only one whose removal fails, or whose user's did, enters the ledger, retryable with its cleanup diagnostic, and the synchronization completes with issues (TXN-07); one anything else uses is released intact. |
