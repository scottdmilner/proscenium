# `tools/build`

The build: the extension's zip and the compiled modules. The packages' build hooks import `native_build.py` and what it imports, and each of those packages names this directory's scripts in its `cache-keys`, so `uv sync` reruns the hook when any of them changes. A script that only uses the build stays in `tools/`. The editable install puts this directory on `sys.path` beside `tools/` (`dev-mode-dirs`), so its modules import by name (`from native_build import sync_module`) in the uv environment, where pytest and the type checkers find them too. Ruff doesn't import anything: its `src` lists this directory, so that it counts these modules as first-party.

| Path | Holds |
|---|---|
| `build_extension.py` | The only distribution build: `dist/proscenium-<version>.zip` for this platform, with the runtime wheels and the planner (`--check`: read-only). It's also the `proscenium-build` command. Releases ship one zip per platform and Blender minor version on GitHub releases ([DECISIONS.md](../../docs/DECISIONS.md) "Native core distribution"). Only the zip's copy of the manifest names the platform and sets `blender_version_max`, so each zip supports one Blender minor version. The workspace's wheels ship only inside the zip, and the extension's own wheel from `uv build` exists only so `proscenium` installs editable in the dev environment. Never publish or distribute either. |
| `native_build.py` | Builds the repository's compiled modules, the planner, the cook, and the Hydra bridge, against the locked Blender release's USD, rebuilding the planner and the cook only when they're out of date, and audits their linkage. Their packages' build hooks build them through it on `uv sync`, unless `PROSCENIUM_SKIP_NATIVE_BUILD` is `1`, as in CI. uv reruns a hook only when one of its package's `cache-keys` changes: after deleting a module by hand, run `uv sync --reinstall-package proscenium_sync` (or `proscenium_cook`). A C++ build error fails `uv sync`, and so every `uv run`, until it's fixed, the variable is set, or the command passes `--no-sync`, as the pre-commit hooks do. The variable is one of the `cache-keys`, so the first sync without it builds the modules it skipped. |
| `blender_deps.py` | Caches the locked Blender release's exact headers (and Windows import libraries) for the compiled modules. |
| `blender_release.py` | The Blender release the project targets: the `bpy` version locked in `uv.lock`. |
