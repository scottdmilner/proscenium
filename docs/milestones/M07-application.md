# M7 — Blender application and source inspection UI

**Implements:** [Blender Application](../spec/pipeline.md#blender-application), the inspection and interaction behavior in [Source Inspection and Interaction](../spec/interaction.md#source-inspection-and-interaction), except correspondence through batching (M8) and instance-root selection (M10), the application side of [Coordinate Conversion](../spec/support/transforms.md#coordinate-conversion), exposing model kind and asset metadata in [Models and Unsupported Content](../spec/support/visibility.md#models-and-unsupported-content), display-correspondence persistence in [Persistence](../spec/lifecycle.md#persistence), stale-content retirement and external-usage protection in [Ownership and Lifecycle](../spec/lifecycle.md#ownership-and-lifecycle), and the display of cached time codes in [Cached Time Codes](../spec/pipeline.md#cached-time-codes) and [Transforms and Time Codes](../spec/support/transforms.md#transforms-and-time-codes), as M4's decision represents them (row "Time-sampled data representation"), except time-varying topology (M8).

**Depends on:** M4 (partitioning decision and finalized interaction contract), M5 (application-layer interface, transaction, and stub tests), M6 (display plans).

**Scope limits:** repair of user-modified content is M11 work.

**Decisions and deliverables:**

- The real application layer for the chosen representation, connected to M5's ownership tracking, transaction, and publishing. It replaces the stub's `prepare` and `key_time_codes` (`synchronization/application.py`): each datablock is held in `PreparedWork` with `track` as soon as it's made, before anything else can fail (TXN-08), and each change a cache call makes to a published resource has its undo appended to `PreparedWork.undo` before it's made (CACHE-03).
- Object names that land at the end of Blender's sorted lists (M6) matter most when synchronizing again, beside the display being replaced: the stub's placeholders, named for their prims, took 7.9 s to prepare on `updates-10000` the second time against 1.1 s the first ([M5 plan](../plans/M05-architecture.md), F3).
- What a full rebuild costs beside its display ([M5 plan](../plans/M05-architecture.md), F1, F2): its undo step holds about the display's size, 1.2 GB on ALab, and its retirement about the datablocks removed times those left in the file, 5.0 s on ALab. Partition-level replacement that keeps unchanged datablocks shrinks both: a step after moving one object held 4.5 MB.
- Partition-level replacement from the start, following the M4 partitioning decision, even though Phase 1 rebuilds everything.
- Basic reconciliation: each synchronization builds a fresh set of partitions, publishes it, and retires the previous result, deleting only obsolete resources that are safe to remove under the ownership and external-usage rules.
- The source inspector, and the agreed browsing, selection, and highlighting behavior from the finalized interaction contract.
- A binding panel that lists a scene's bindings once per draw, measured against M4's interaction budgets: a listing reads every collection's binding records, 13 µs with one binding (DECISIONS.md "Binding records read when called").
- From M4's selection tool ([M4 plan](../plans/M04-prototypes.md), F2, F3): whatever owns the destination's display, not a selection tool, decides when managed content is selectable (the destination collection's `hide_select`, 44 ms on ALab against 0.95 s per object) and which overlays the 3D views hide, as later tools may need it selectable; the active tool's changes come from message-bus subscriptions to `WorkSpace.tools` and `Window.workspace`. A file saved while Source Select is active keeps those settings, so loading restores or ignores them. Blender's own outlines stay the default; outlines of the extension's own would need a C-level draw engine to reuse Blender's GPU geometry and dim what is hidden. A box selects elements by their world bounds' centers, since many copies hold their placement in their points.
- Cached time codes for every variation (CACHE-10), with mechanisms suggested and not probed ([M4 plan](../plans/M04-prototypes.md), F5): a copy's materials chosen by a keyed index (a Geometry Nodes Set Material fed by an Index Switch), or an object per material state with keyed visibility; a placeholder's bounds box and empty marker both made, each with keyed visibility; and a property keyed, where its primvar is blocked, with its reader's fallback (M9). A batch has an object per selection state its instances hold (D14).
- The inspection layer of the [interaction contract](../spec/interaction-contract.md#two-layers-and-the-live-stage): a C++ library that maps picked prims to selection targets by kind on the live stage, independent of the compiled core and of Blender, which the core calls and exposes through its bindings. It reads the live stage M3 defines for each binding. It follows the core's type-identity rule, and registers any Tf-factory type through an exported USD helper, as Hf's plugin registry does, never by deriving from a header-only factory base: a keyless UsdImaging adapter built that way failed on macOS with "Cannot manufacture type" ([M1b plan](../plans/M01b-evaluation-gate.md#phase-c-log)).
- Selection maps back through the plan's correspondence, never through `HdxPrimOriginInfo`, which is quadratic in the instance count in Blender's USD (v26.03): 1,330 ms against 25 ms at 50,000 objects ([M1b plan](../plans/M01b-evaluation-gate.md#phase-b-log)). A plan index names an element within one generation only, so a pick held across a republish needs the element's resource identity ([M4 plan](../plans/M04-prototypes.md), B3).
- From the bridge's application path:
  - A moved object that fails to publish is restored from the location, rotation, and scale Blender stored, not from its old matrix, which can decompose under another sign convention ([M4 plan](../plans/M04-prototypes.md), E2).
  - Every object of a cached mesh gets its frames modifier when the mesh is written ([M4 plan](../plans/M04-prototypes.md), E5). The modifier goes first in the stack, ahead of a carrier's batch modifier, and a FLOAT2 sample is stored as a 3D vector, since a 2D vector on corners becomes a UV map (the bridge's `keyframes.py` and `attribute_samples.py`).
  - Indexing a Vt array from Python costs about 48 µs a record, about 0.34 s of the object baseline's construction on ALab, so application reads converted values ([M4 plan](../plans/M04-prototypes.md), D5).
- Memory measured with the depsgraph's evaluated copies in mind: they hold their memory until its next evaluation, 1.7 GB after deleting the importer's ALab data ([M1b plan](../plans/M01b-evaluation-gate.md#phase-e-log)).

**Tests:**

- Resulting Blender content and source correspondence for hand-constructed plans.
- Repeated application: several unchanged synchronizations follow [Resource Stability](../spec/lifecycle.md#resource-stability), with stable active counts, stable total managed counts when disposal succeeds, separately tracked leftovers during disposal failure, and count recovery after explicit cleanup.
- The M5 failure-injection tests, rerun unchanged against the real application layer.
- Application-time resource failures abort the transaction unless the plan authorized a fallback.
- `F-UNMANAGED-USER`.
- `F-OFFLINE`: correspondence records unchanged through reopening with the source unavailable (REOPEN-07).
- The M4 interaction checks against the real display: `F-KIND-HIERARCHY`, `F-NESTED-SELECTION`, `F-UNIVERSE-MEMBERSHIP`.
- Model kind and `assetInfo` read from a binding's live stage on `F-KIND-HIERARCHY` (MODEL-01).
- End-to-end tests using M6-generated plans.
- Cached time codes: synchronized at one sampled time code and cached at the others in more than one order, each frame displays what a clean synchronization at its time code does, whether they were cached in one call or several, and a frame between them the latest before it, with interaction answering for that time code; the display caches nothing on its own (CACHE-01, CACHE-08, CACHE-09, CACHE-10, XFORM-11, XFORM-13, XFORM-14).

**Exit condition:** the application layer displays and inspects plans, passes the M5 failure-injection suite and `F-UNMANAGED-USER`, and meets the boundary rule in Blender Application.
