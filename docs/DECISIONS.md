# Decision Register

Milestones update this register when they settle a decision. Every in-scope requirement is traced in the requirement-to-test matrix created in M1, with high-risk entries marked separately by M4. Settled contract decisions update their requirement rows and test/oracle coverage before implementation. Fixture IDs refer to [Named Contract Fixtures](testing/strategy.md#named-contract-fixtures).

| Inspection layer | M2 / M7 | **Chosen (with the user, 2026-10-15):** a C++ library that maps picked prims to selection targets by model kind on the live stage. | Native core distribution | M1b | **Chosen (with the user, 2026-10-14): GitHub releases**, one extension zip per platform and Blender minor version, which users install from disk. M3 adds the core's build to `tools/build_extension.py`; M1b's check packages the feasibility bridge in its own test zip. Not listed on extensions.blender.org, so its rule against compiled code (Terms of Service §3.6) doesn't apply; a rebuild and new release for each Blender minor version that changes USD is acceptable (settled 2026-10-09). Blender's dependency headers are pinned per Blender release. Not chosen: a self-hosted extension repository, or both. **Risk:** the module binds to Blender's exact USD build (namespace `pxrBlender_v26_03__pxrReserved__`), so each zip needs a `blender_version_max`. Untested: a download through a release page (macOS quarantine), and updating or uninstalling while the module is loaded. | Time-sampled data representation | M1b / M4 | Open. Treating time codes as frames and authoring animation data is permitted ([Transforms and Time Codes](spec/support/transforms.md#transforms-and-time-codes)) but not preferred. **M1b findings** ([record](feasibility/runtime-record.md#for-m4-evaluating-frames)): the core evaluates one time code per capture, and caching several frames is a layer above capture. Capture matches USD at each time, and a time change dirties exactly the varying values (equal samples included), so successive captures say what changed. Direct USD (`ValueMightBeTimeVarying`, `GetTimeSamplesInInterval`) gives authored keys when a representation needs them. Hydra's interval query is a motion-blur API and isn't needed. M4 compares per-time-code snapshots against animation-data representations: keyframed transforms, mesh cache modifiers, and **Geometry Nodes baking**, which is expected to perform better at the cost of higher memory use (to be measured). M4 records the time-code-to-frame mapping for any it adopts. Mesh cache modifiers that read the USD file must first reconcile the application-boundary, in-memory-source, offline-reopening, and pre-mutation-diagnostics requirements listed in [M1b](milestones/M01b-evaluation-gate.md). | M1b feasibility record; M4 prototypes and measurements |
