# Import checks with import-linter: plan

How the workspace's [import rules](../../packages/README.md#import-rules) come to be checked by [import-linter](https://github.com/seddonym/import-linter) in place of `tests/bpy_free/test_import_tiers.py`. It changes no behavior and adds no requirement. The rules change in one place: what a package may import of another package becomes that package's public API ([Public APIs](#public-apis)).

## Why import-linter

`test_import_tiers.py` reads every module's imports with `ast` and checks them against tiers, exports, and dependencies that it and the READMEs each spell out. import-linter checks the same rules as contracts, `[tool.importlinter]` in each library package's `pyproject.toml` for the package's own rules, and in the root `pyproject.toml`, the extension's project, for the extension's and those between packages. Each package's rules live beside its code, and the READMEs and AGENTS.md describe the rules and link to the contracts instead of restating them.

It builds one import graph over the three packages, `proscenium`, `proscenium_sync`, and `proscenium_ui`, from their source, so an import between packages is checked as precisely as one within a package, and the imports of external packages such as `bpy` are in the graph too. The graph counts every import: at module level, inside a function, and under `TYPE_CHECKING`, as the rules do. Its `layers` contracts follow chains of imports through other modules, not only direct ones, which is stricter than the test and holds on the tree now.

A rejected alternative still guides the configuration: tach checks imports between packages only by distribution, and matches import paths, so it can't tell a private module from an exported name without a list of each unit's exports.

## Contracts

These contracts pass on the tree, each file in under a second without import-linter's cache. Each check below was shown to fail on its violation injected into a copy of the tree.

- **Tiers.** One `layers` contract per package, highest first, with the package as its container. Units of one tier share a line (`synchronization | interaction`), which also keeps them from importing each other, and so does the lowest tier's `planner | source_access | results`. Checked: an import of a higher tier at module level, inside a function, and under `TYPE_CHECKING`; an import between units of one tier; and one between lowest-tier units.
- **Every module is a unit's.** The tiers' contracts are `exhaustive`, so a module added beside the units that no tier lists fails. `exhaustive` takes only a container's children, so each of `proscenium_ui`'s widgets, one unit of its top tier, has a contract of its own, its `display` above its model, exhaustive over the widget's children. A model stays below Blender's units by the bpy-free contract, which follows imports through other modules, not by the tiers. Checked: a stray module in `proscenium_sync`, and one in `scene_graph_widget/`; `prim_tree` importing its widget's `display`, and the other widget's `display` and model; `widget_resources` importing `prim_tree`; and `prim_tree` importing `columned_list`, which the bpy-free contract catches.
- **A unit is reached through its exports.** A unit whose `__init__.py` exports names rather than all of its modules has a `protected` contract over its modules, which only the unit itself may import: `proscenium_sync.synchronization.*`, allowed to `proscenium_sync.synchronization`, and likewise `bindings`, `results`, and the two widgets' `display`. The planner, which exports names, has none: its names are its compiled module's, which import-linter doesn't see, so its only Python module is its `__init__.py`, and a `protected` contract over no module can't fail. Another unit then imports only the package, so only what its `__init__.py` defines or imports, and ty rejects a name that it doesn't (`unresolved-import`). A unit that exports all its modules needs no contract. So no contract lists a unit's names, which are written once, in its `__init__.py`. Checked: `bindings` importing `synchronization`'s `application`, and a name `persistence` doesn't export.
- **Package dependencies.** One `layers` contract over the three packages, `proscenium` above `proscenium_sync | proscenium_ui`: neither library package imports `proscenium`, and neither imports the other. Checked: `proscenium_sync` importing `proscenium_ui`, and `proscenium_ui` importing `proscenium`.
- **The public APIs** ([Public APIs](#public-apis)): a `protected` contract per library package over its units, which only the package itself may import, so another package imports only the package itself: `proscenium_sync`'s, with no exception, and `proscenium_ui`'s with `ignore_imports` naming what the extension may, the two widgets' `display` and `widget_updates`. Checked: `interface/` importing `proscenium_sync.runtime`.
- **The bpy-free tiers** (`planner/`, `source_access/`, `results/`, `widget_model/`, `prim_tree/`, `property_list/`): a `forbidden` contract on `bpy` and Blender's other modules (`mathutils`, `idprop`, `gpu`, `gpu_extras`, `bpy_extras`, `blf`, `bmesh`), with `include_external_packages`. Every contract lists the same modules, which `tests/bpy_free/test_import_contracts.py` checks, since TOML can't share a list between files. Checked: `bpy` under `TYPE_CHECKING` in the planner, `mathutils` inside a function in `results/`, and a lowest-tier unit importing the planner after the planner imported `bpy`.
- **The library packages' own `__init__.py` files,** and the widgets' (`scene_graph_widget/`, `property_viewer_widget/`), import without `bpy`: the same `forbidden` contract over those modules alone (`as_packages = false`), following their imports. `proscenium_sync`'s loads its API with `importlib.import_module`, which no contract sees, so its contract checks only its static imports, and `test_no_blender_imports.py` what importing it loads. Checked: `scene_graph_widget/__init__.py` importing `display`, which imports `bpy`.
- **A unit's modules import each other without cycles:** `acyclic_siblings` over each package's units, and over the widgets' (`proscenium_ui.*.*`). Checked: two of `widget_model`'s modules importing each other.

import-linter doesn't see the planner's compiled `_planner`, since its graph holds only Python source, so `from proscenium_sync.planner import _planner` outside the planner reads to it as an import of the planner. The planner's README says the module is the package's own, so callers write `planner.Plan`.

`tests/` and `tools/` are no root package, so no contract checks them: tests reach into any module, and `tools/row_icon_masks.py` reads a column module.

`test_no_blender_imports.py` stays: it imports the bpy-free code with Blender's modules blocked, which no static check does. `test_application_imports.py` (APP-08) stays as it is: it skips type-only imports, which every contract counts.

## Public APIs

The rule that `interface/` imports only `bindings/` holds because `bindings/` is the synchronizer's API. Since the packages split, that is a rule about `proscenium_sync`, not about `interface/`: **each library package names its public API, the units another package may import, and no other package imports anything else of it.** Within a package, the tiers still apply.

- **`proscenium_sync`'s public API is its own names:** what `bindings` exports, and `registration`'s `register` and `unregister`. Callers write `proscenium_sync.BINDINGS`, `proscenium_sync.BindingHandle`, and `proscenium_sync.register()`, and import nothing below the package, so its contract protects all its units with no exception. The package's `__init__.py` still imports without `bpy`, so importing the planner never loads Blender: it imports none of its units, and loads the API's on first use, through a module `__getattr__` (PEP 562), from one literal map of each unit to the names it gives. `__all__` is the map's names. A stub beside it, `__init__.pyi`, gives type checkers and editors their real types: `from .bindings import *`, so `bindings`' `__all__` stays the one list of its names, and `registration`'s two functions. import-linter reads no stub, so no contract needs an exception for it; imports under `TYPE_CHECKING` in the `__init__.py` would reach `bpy` through the planner, whose compiled module import-linter reads as an import of `proscenium_sync`. `tests/bpy_free/test_sync_api.py` checks that the map and `__all__` name what the stub imports, and `test_no_blender_imports.py` keeps checking that `import proscenium_sync` loads no `bpy`. An error in an API module surfaces on first use rather than at `import proscenium_sync`. Blender imports the extension's `addon.py` at registration, which uses the API at once, so in practice the timing is the same.
- **`proscenium_ui`'s public API** is the widgets, `scene_graph_widget.display` and `property_viewer_widget.display`, and `widget_updates`, whose `schedule` and `unschedule` a host uses, as the widgets do, to defer what a draw may not do. Each is imported as a module (`from proscenium_ui.scene_graph_widget import display`). Their names overlap (`create_view`, `set_stage`, `register`, `ViewNotFoundError`), so they can't share one namespace at the package's top.
- **Every other library `__init__.py`,** `proscenium_ui`'s and the widgets', holds only its docstring.
- **The extension's units** may import either package's public API, and `addon.py` and `interface/` keep their tiers: `addon.py` registers the synchronizer and the temporary UI.
- **When Blender's Python reaches 3.15,** PEP 810's `lazy from .bindings import BindingHandle` replaces the map, `__getattr__`, and the stub. Blender 5.2 bundles 3.13.

## CI and tooling

- import-linter goes in the `lint` group, pinned through `uv.lock`, like ruff.
- A pre-commit hook per file of contracts, `uv run --frozen lint-imports --no-cache --config <its pyproject.toml>`, with `pass_filenames: false`: a package's runs on its Python files and its `pyproject.toml`, and the root's on every Python file and `pyproject.toml`, since it checks the imports between packages. import-linter 2.16 reads one configuration a run; a later release that takes several in one run (`lint-imports pyproject.toml packages/*/pyproject.toml`) makes them one hook. CI runs them through `pre-commit run --all-files`, as it does every lint check. They find the three packages through the dev environment's editable installs.
- `--no-cache`: a run with import-linter's cache missed an edit made just after an earlier run, and each file takes under a second without it. The cache directory, which a run by hand makes, is ignored by Git.

## Commits

Each commit is one change, passes `pre-commit` and the test suite on its own, and updates the docs, READMEs, and tests that name what it changes.

1. The plan, written for tach.
2. **`results.py` becomes `results/`:** its diagnostics and its result in a module each, behind an `__init__.py` that exports their names.
3. **This plan,** for import-linter.
4. **import-linter checks the import rules:** the lint group, the contracts in each `pyproject.toml`, their hooks, and the tier tables' move into the contracts. `test_import_tiers.py` goes, its `interface/` rule becoming the public-API contracts. AGENTS.md and the READMEs follow.
5. **`proscenium_sync`'s API at its top:** the lazy `__init__.py`, its `__init__.pyi`, its `bpy_free` test, the extension's imports of `bindings` and `registration` becoming `proscenium_sync`'s names, and its public-API contract protecting every unit.

## Decision log

- **Adopt import-linter (with the user, 2026-11-17).** Its contracts check every import rule, between packages as within them, so no test reads imports itself. Each library package's contracts are in its own `pyproject.toml`, beside its code, and the root's hold the extension's and those between packages. Tach, tried first, checks imports between packages only by distribution, and couldn't check a unit's exports without either a list repeating each `__all__` or every private module renamed to begin with an underscore.
- **What a package may import of another is that package's public API (with the user, 2026-11-17).** The rule that `interface/` imports only `bindings/` predates the packages. Since they split, the boundary is the package's, and it holds for every importer: `proscenium_sync`'s public API is `bindings`' exports and `registration`'s two functions, and `proscenium_ui`'s is its widgets and `widget_updates`.
- **`proscenium_sync` exports its API from its top, loaded by a module `__getattr__` (with the user, 2026-11-17).** The package's `__init__.py` stays importable without `bpy`, which the planner's tests and SNAP-08's oracle need, while its `__all__` is the API. `importlib.util.LazyLoader` defers a module's execution, not a name's, so getting an exported name from a lazy module runs it at once. PEP 810's `lazy from` needs Python 3.15, and the third-party `lazy_loader` would be one more bundled wheel for the same `__getattr__`.
- **`__all__` stays the one list of a unit's exports (with the user, 2026-11-17).** The `protected` contracts guard a unit's modules, not its names, and ty rejects an import of a name an `__init__.py` doesn't define, so no configuration repeats it.
