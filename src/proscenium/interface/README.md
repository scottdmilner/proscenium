# `proscenium.interface`

The temporary UI, which M12 replaces (M7 plan, settled 3): the Source Select tool, minimal panels, and a node tree for testing the cook in Blender. It uses only the packages' public APIs, so replacing it touches neither the product nor the widgets: it reaches the product, the bindings, their synchronization, and interaction with their displays, only through `proscenium_sync`'s names, and the cook only through `proscenium_cook`'s, and a widget only reads a stage its host gives it. Its operators declare `UNDO` only where the API pushes no undo step of its own, as for a selection; an operator calling an API function that pushes one, such as a synchronization, declares none.

Code in other units reaches it through the modules `__init__.py` exports ([import rules](../README.md#import-rules)); tests reach into any module.

| File | Holds |
|---|---|
| `__init__.py` | The package's exports: its modules. |
| `source_select_tool.py` | The Source Select tool, ported from the bridge's `select_tool.py`: a click picks what its own ray hits as the display draws it, each object's bounds box or an empty marker near its origin, shift toggles and ctrl removes, a drag selects a box by elements' world bounds' centers, and the sidebar's Proscenium tab sets the level and lists the scene's targets. Managed content is selectable exactly while a window showing it has the tool active, which message-bus subscriptions to the workspaces' tools and the windows' workspaces follow. |
| `binding_panel.py` | The binding panel in the sidebar's Proscenium tab: an add button, whose operator picks a USD file and creates a binding on the scene, named for the file, with its stage attached, declaring `UNDO` since creating a binding pushes no step; then the scene's bindings, listed with one call per draw (`Bindings.binding_statuses`), each with its name, attachment, and state or why it can't be used, a synchronize button, and a remove button (`Bindings.remove_binding`); a binding that can't be used has neither, since both would refuse it, and a binding with copies (`Bindings.copied`) has no remove button, which removal refuses; each row says why. Neither operator declares `UNDO`, since the API pushes their steps; a removal that leaves disposals pending warns. |
| `source_inspector.py` | The source inspector in the sidebar's Proscenium tab: `proscenium_ui`'s scene graph widget over the live stage of the binding its dropdown chooses, the inspector holding no stage, and whether the prim selected in the tree is displayed. With its sync toggle on, the tree's selected prim and the scene's source selection mirror each other, a row selecting its prim's floor as an undo step, and the source selection selecting its active entry's row. Below the tree, the property viewer widget shows the selected prim's properties at the time code the display shows, and a target's jump button selects its prim in the tree. |
| `cook_node_types.py` | The cook's node tree type, Proscenium, with its Viewer dropdown (the Viewer node the cook runs, by name, which a tree's first Viewer is set to when it's made), its socket per socket kind, and a node type per definition in `proscenium_cook.NODE_DEFINITIONS_PATH`, built when the extension registers: each input and output a socket, identified by its attribute's name, each property a `prop_<name>` node property, and a begin's `zone_end`, its end node's name. Its node types are in the node editor's add menu. A link the cook would reject (`proscenium_cook.link_problem`) is drawn red and kept, marked on a timer after each update of the tree, since Blender's own pass marks every link valid, and for every cook tree after a file loads or an undo step. |
| `cook_tree_layer.py` | The tree written as the cook's tree layer, in the note's format: `/Tree`, a prim per node named by `proscenium_cook.prim_name_from_node_id`, each link a connection, past reroutes, and each value only where it isn't the definition's default. |
| `cook_panel.py` | The Cook panel in the node editor's sidebar Proscenium tab: a button that cooks the edited tree, with the Viewer its Viewer dropdown names, and prints the tree's diagnostics, each node's report, and which nodes have a stage to the console, and gives the Viewer's stage to the cook inspector; with the tree's Print Tree Layer checkbox on, the tree's layer too. Each tree's stage and `TreeCook` are kept between cooks, keyed by its session UID, and dropped when a file loads. It hands no stage to a binding. |
| `cook_inspector.py` | The cook inspector, below the Cook panel in the node editor's sidebar Proscenium tab: `proscenium_ui`'s scene graph widget over the last cook's Viewer stage, while the edited tree is the one cooked, and the property viewer widget over the prim it selects, with a target's jump button selecting its prim. The tree's kept cook holds the stage, not the views. |
| `interface_registration.py` | Registration of the UI's scene property, classes, the cook's node types, `proscenium_ui`'s widgets, whose views each inspector adds and removes on its own, tool, and subscriptions; the load handler, which subscribes again and drops the kept cooks; and the load, undo, and redo handlers, which recompute selectability from the active tool and mark the cook trees' incompatible links. |
