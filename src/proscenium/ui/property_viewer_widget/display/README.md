# `proscenium.ui.property_viewer_widget.display`

The property viewer widget's display: the `property_list/` model drawn in Blender as a virtualized `UIList`, for a host to place ([Property Viewer UI](../../../../../docs/phase3/property-viewer-ui.md#the-widget)). It registers no panel that shows by itself: its one panel is the settings popover its gear opens. A host registers it, creates named views, saying for the key watcher which regions are showing each, gives each a stage and then a prim on it, such as the prim a scene graph view selects, and calls `draw_properties` and `draw_metadata` from its own panels' `draw`; it may hear each view's selection changes and take its targets' jumps, and give it a time code to show values at. A host holds only a view's name, and changes and reads it through the package's functions.

Each view's state is a `property_list.PropertyListView`, and the UIList draws from an item of the window manager's `proscenium_property_viewer_views` collection named for the view: one empty row item per visible row, the active row, the search fields, and the column settings. The item mirrors the view, apart from the search fields, which hold the query being edited until it's applied to the view. The window manager's properties aren't saved, so a load handler makes the items again after each load, from the views.

It draws with what the widgets share: the theme's colors, badge icons, the tree rows' widths, guide lines, and badges, the key watcher, and the copy-path operator from `widget_resources/`, which its registration registers too; columns, their header and settings from `columned_list/`; the search box from `search_box.py`; and timers from `widget_updates.py`.

Its modules import each other in the order the table lists them, each only from those above it; `tests/bpy_free/test_import_tiers.py` fails on any cycle among a unit's modules.

| File | Holds |
|---|---|
| `__init__.py` | The package's exports: the names hosts use, `register`, `unregister`, `is_registered`, `create_view`, `remove_view`, `set_stage`, `show_prim`, `set_time_code`, `select_property`, `selected_path`, `draw_properties`, `draw_metadata`, `apply_pending`, and `ViewNotFoundError`. |
| `property_viewer_views.py` | The views by name, each a `PropertyViewerView`: its `PropertyListView`, where its host shows it, who hears its selection and takes its jumps, and its timers, and which views' search text is being typed. It knows nothing of Blender's data, and hosts never see it. |
| `property_viewer_properties.py` | The property groups a view is drawn from, `PropertyViewerViewProperties` (one view's rows, active row, search fields, on with only authored properties shown, and settings: which columns show, the Type column hidden by default, its width, and the Value column's share of the row, wider than the name's) and `PropertyViewerRow` (a row item with only a computed tooltip), with their update callbacks, the window manager's collection of them, and everything that reads or writes them: making a view's item from the view, syncing its row items with its list, reading its search fields, `apply_stage_changes`, which a view's stage timer calls to read stage changes once an edit is over, and `apply_pending`, which its search timer calls to apply a search a pause after the fields last change, reading any stage changes too. |
| `property_viewer_keys.py` | The views as lists the shared key watcher (`widget_resources/list_keys.py`) steps: Right shows a property's targets, or steps into its first; Left hides them, or steps out of a target to its property; with Shift, every property's show or hide. A view whose search text is being typed leaves the keys to its text box. `start_watching` and `stop_watching` add and take them. |
| `property_viewer_operators.py` | `PropertyViewerToggleRow`, the disclosure triangle that shows or hides a property's targets (Shift: every property's), and `PropertyViewerJumpToTarget`, a target's jump button, which hands the target's path to the host's `on_jump_to_target` to select where it shows it; each with its tooltip from its `description`, internal, pushing no undo step. |
| `property_columns.py` | The list's columns: the name column, which draws a row as a tree's (a target's indent and guide line, the chevron, the row's icon, its name or target's name, and its keyframe icon), and the Value column, which on a target's row holds its jump button and path, and the Type and Copy Path columns after it, each drawing its cell from a `PropertyCell`, a row and its property's details. |
| `prim_summary.py` | The summary of a view's prim above its list, read once per list from what the scene graph's model reads of a prim: its path; its type, specifier, and kind on one line; anything unusual; and its instancing and composition arcs, a line each led by the scene graph's badge, greyed as it greys them; drawn with its lines closer together than rows. |
| `property_viewer_drawing.py` | `PropertyViewerList`, the UIList, which draws each row's name cell and then the cells of the shown columns after it; `PropertyViewerSettings`, the popover a gear at the status line's end opens for a view's settings; `draw_properties`, with the prim's summary and the header row above the list, and the search box and the status, with the settings gear, below it; and `draw_metadata`, a summary of the selected property. |
| `property_viewer_hosting.py` | What a host calls: `create_view`, `remove_view`, `set_stage`, `show_prim`, `set_time_code`, `select_property`, and `selected_path`. |
| `property_viewer_registration.py` | `register` and `unregister`: the shared display, the classes, the window manager's collection, the views' key watching, and the load handler that makes each view's properties again and ends any text edit. |
