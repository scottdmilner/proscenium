# `proscenium.binding.persistence`

Everything the extension saves in the `.blend`: versioned records in Blender ID properties ([Persistence](../../../../docs/spec/lifecycle.md#persistence)). Tier 2: it may import only the lowest tier (`proscenium.core`, `proscenium.binding.source_access`, `proscenium.binding.results`).

| File | Holds | Records, and where they are |
|---|---|---|
| `__init__.py` | The package's exports: its modules, each one kind of record and the functions that read and write it, which code in other units imports ([import rules](../../README.md#import-rules)); tests reach into them. It imports `configs.py`, which needs `bpy`, so the package and every module in it import only with Blender; their tests are in `tests/blender/`. | |
| `records.py` | The versioned-record framework: `Schema`, loading with migration, `Loaded` and `RefusedRecord`, reading, writing, and removing records, and `NAMESPACE`, the records' ID-property group. | |
| `configs.py` | `BindingConfig`, `DestinationTag`, and `BindingIndex`, with binding creation (`create_binding`), restoring an index entry (`restore_index_entry`), and the reads that find every binding's records. | A binding's configuration on its target scene, the tag on its destination collection, and the binding index on its own Text. |
| `manifests.py` | Ownership metadata: `Manifest` and `ManifestEntry`, keyed by random entry keys (`new_entry_key`), each entry's `RepresentationRole`, and a copy's resources' `CopyResourceIdentity`, by which a prepared resource takes a published entry's key (`entry_keys`). They're written whole (`write_manifest`) or by entry (`write_manifest_entries`), and removed (`remove_manifest`) ([Ownership and Lifecycle](../../../../docs/spec/lifecycle.md#ownership-and-lifecycle), [Representation Roles and Resource Identities](../../../../docs/spec/lifecycle.md#representation-roles-and-resource-identities)). | A binding's manifest on its destination collection. |
| `ledgers.py` | The pending-cleanup ledger: `Ledger` and its `LedgerEntry`s, keyed by random ledger keys (`new_ledger_key`), each holding a pending resource's binding, entry key and role, datablock, `OriginatingOperation`, `RetryStatus`, and cleanup diagnostic. Written by entry (`write_ledger_entries`) ([Pending Cleanup](../../../../docs/spec/lifecycle.md#pending-cleanup)). | On the binding index's Text, beside the index. |
| `binding_state.py` | `Generation`, what the published display was produced with, which publication writes and its undoing removes (`remove_generation`), and `LastAttempt`, the most recent synchronization attempt ([Binding State](../../../../docs/spec/lifecycle.md#binding-state)). | The generation on the destination collection, beside the manifest; the last attempt on the target scene. |
| `selection.py` | `PersistentSelection` and its `SelectionEntry`s ([Persistent Selection](../../../../docs/spec/interaction-contract.md#persistent-selection)). | On the scene. |

## How records work

- **Where they are:** each ID that carries records holds them in one ID-property group, `id_["proscenium"]`, one record per key. `addon.py` registers that group's name as a property group, so Blender's Custom Properties panel hides it, but the records are plain ID properties, readable with the extension disabled.
- **Versions:** every record stores its schema version, and every schema is at version 1. Reading migrates an older supported record in memory, and the next write stores it at the current version. Binding configuration stores the last attached root-layer identifier, destination, and settings.
- **Refusals:** a record that can't be read, being newer, damaged, or failed in migration, loads as a `RefusedRecord` value, never an exception, so its binding keeps its display and reports why. Writers read before writing and refuse on any refusal, and writing itself refuses to replace an unreadable or newer record ([Schema Versions](../../../../docs/spec/lifecycle.md#schema-versions)).
- **Pointers:** a record names datablocks by ID pointer, not by name. Blender clears a pointer when its datablock is removed, and a full-copy scene or an append rewrites the copies' pointers to each other, while `Collection.copy()` keeps them naming the originals ([copy routes](../../../../docs/feasibility/runtime-record.md#copy-routes-m3)).

The binding index and the ledger are on a Text rather than a scene or collection, so no copy route copies them ([Canonical Candidate](../../../../docs/spec/source-access.md#canonical-candidate), DECISIONS.md "Pending-cleanup tracking mechanism").
